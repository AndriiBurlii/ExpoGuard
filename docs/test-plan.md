# План перевірок

Це критерії приймання. Стан фактичних перевірок ЛР1 зберігається у [validation/README.md](validation/README.md). Усі тести ЛР2 нижче ще не виконані.

## ЛР1

| ID | Дія | Критерій |
|---|---|---|
| B-01 | `make clean`, `make build IMAGE=expoguard-lr1-build:local` | Exit 0, ELF/HEX/BIN існують, повний лог збережений |
| B-02 | Повторити B-01, порівняти SHA256 трьох файлів | Однакові хеші для двох чистих збірок тієї самої копії з тим самим образом; не доказ ідентичності на іншій архітектурі |
| B-03 | В Ubuntu 24.04 записати `/etc/os-release`, `uname -m`, Docker version, повторити B-01/B-02 | Справжній VM лог і хеші, без підміни логом Mac |
| B-04 | VS Code F1 → `Wokwi: Start Simulator` у ExpoGuard | У цьому проєкті видно ready, щонайменше tick 1/2/3; за 10 с видно кілька змін LED |
| B-05 | Зіставити timestamp UART та LED з кодом | Tick приблизно щосекунди симуляції, LED змінюється приблизно раз/с; повний цикл близько 2 с. Точність потребує вимірювання, screenshot не доводить період |
| B-06 | Перевірити історію Git та вміст дерев | Один порожній main, 4 змістовні коміти feature/lab-1, погоджені author/committer дати, чистий робочий каталог |

## ЛР2

| ID / FR | Вхід та дія | Очікуваний результат |
|---|---|---|
| T-01 / 01,02 | Reset, команди `mode guard`, `mode expo`, `mode move`, `mode unknown`, порожній рядок; до guard виконати calibrate | Старт expo; guard без бази відхилено; валідні переходи підтверджені до 200 мс, невідома команда не змінює стан |
| T-02 / 03 | PIR Simulate Motion, повтор до кінця HIGH, потім після LOW та inhibit; повтор у трьох режимах | Одна visitor_motion на LOW→HIGH до 100 мс; HIGH не дає дубль, тривоги немає. Кількість подій не дорівнює кількості людей |
| T-03 / 04 | Задати accel 0,0,1 g та rotation 0; змінити X на -1 g, gyro X на 50 °/с | Знак і одиниці правильні, вибірки 20 мс, UART telemetry ≤2/с; інтервал перевірити інструментуванням |
| T-04 / 05 | Калібрувати 0,0,1; guard; accelX=0.29, 0.31 g у двох вибірках, gyroX=29,31 °/с | Нижня межа не активує, верхня активує LED/model_motion до 100 мс після підтвердженого порога; одинична вибірка не активує |
| T-05 / 06 | Повторити рух T-04 в expo і move; LDR темний, PIR HIGH | В expo інформаційна механічна подія, у move authorized_motion, механічна тривога не виникає |
| T-06 / 07 | 100 стабільних вибірок, потім calibrate з розкидом 0.06 g або gyro 4 °/с | Стабільна база прийнята, рухома відхилена; попередня база збережена |
| T-07 / 08,09 | ADC крайні значення; 69/71% та 59/61% шкали; коливання між 61..69%, PIR LOW, MPU спокій | Правильний ADC 0..4095; фільтр 5 вибірок і гістерезис; від світла немає механічної тривоги |
| T-08 / 10 | Створити події, reset, повторити | Кожен запис має uptime/mode/source/value; після reset uptime з нуля, збереження журналу не обіцяється |
| T-09 / 11 | Від'єднати MPU або підмінити HAL результат NACK/timeout, паралельно PIR і UART-команди | sensor_error, дані невалідні, повтор ≤1/с; PIR до 100 мс, команда до 200 мс, ADC продовжується |
| T-10 / 12 | Тривалий рух, ack під час руху, 2 с спокою та ack, новий рух | Ack під рухом відхилено; після спокою LED вимкнено, новий рух знову активує; записи ≤1/с |

Спільний тест: 60 с режиму guard із валідною базою, частими PIR подіями, змінами світла, механічними імпульсами та UART-командами. Порівняти input timestamp і log timestamp, зафіксувати найгіршу затримку. Секундний блокуючий `HAL_Delay` шаблона для цього непридатний. ЛР2 потребує планувальника за `HAL_GetTick`, обмежених HAL timeout та UART буфера; зараз це не реалізовано.

Wokwi задає значення вимірювань, а не доводить фізичну чутливість PIR чи механіку удару. Зберігати версію прошивки, параметри вхідних сигналів, сирі логи та фактичні pass/fail, включно з невдалими тестами.
